# DoTask for iPhone: from this repo to the App Store

There is no Mac. GitHub Actions builds, signs and uploads the app on a macOS runner
(`.github/workflows/ios.yml`). Everything Apple-side is done in a web browser or on your iPhone.
Store texts, App Privacy answers, age rating and review notes live in `mobile/store/`
(`app-store.md`, `review-notes.txt`).

## What is already set up in the project

| Where | What and why |
|---|---|
| `ios/App/App/Info.plist` | Display name DoTask; microphone and camera purpose strings (the voice tutor and "Show my camera"); `ITSAppUsesNonExemptEncryption = false` (only system HTTPS, so no export questions per build); URL scheme `com.agapecare.dotask` so Canvas sign-in (`com.agapecare.dotask:/oauth/canvas`) returns to the app. No photo-library keys: photos come from the system picker, which needs no permission. |
| `ios/App/App/PrivacyInfo.xcprivacy` | Privacy manifest: no tracking; collected data types matching the App Privacy answers; required-reason APIs UserDefaults `CA92.1` (Preferences plugin) and FileTimestamp `C617.1` (Filesystem plugin). Change it together with App Privacy. |
| `ios/App/App.xcodeproj/project.pbxproj` | iOS 16.4 minimum (the app needs `DecompressionStream('deflate-raw')` and a reliable AudioWorklet); iPhone only (`TARGETED_DEVICE_FAMILY = 1`, so no iPad screenshots); version `MARKETING_VERSION = 2.1.0`. The build number is set by CI. |
| `ios/ExportOptions.plist` | App Store Connect export with direct upload and automatic signing; CI fills in the team ID. |
| `ios/App/CapApp-SPM/Package.swift` | Regenerated by `npx cap sync`; do not edit. Its `.iOS(.vNN)` floor is copied from the major of the first `IPHONEOS_DEPLOYMENT_TARGET` (so `.v16` after the next sync; the `.v15` in the file now is from before 16.4 was set). `App/App/public`, `capacitor.config.json` and `config.xml` are generated too. |

For each new App Store version: raise `version` in `mobile/package.json` and `MARKETING_VERSION`
(two places, Debug and Release) in `project.pbxproj` to the same number.

## 1. Apple Developer Program (once)

1. Use an Apple Account with two-factor authentication on. Enroll at developer.apple.com/programs/enroll,
   or in the Apple Developer app on your iPhone (easiest: it scans your photo ID for identity verification).
2. Fee: US$99 per year. As an individual, your legal name is shown as the seller on the App Store.
   As an organization (for example Agape Care) you need a D-U-N-S number, and verification takes longer.
3. Wait for the "Welcome to the Apple Developer Program" email (hours to a few days).

## 2. App Store Connect (once, web only)

1. Bundle ID: developer.apple.com/account, Certificates, Identifiers & Profiles, Identifiers, "+",
   App IDs, App. Description `DoTask`, Explicit Bundle ID `com.agapecare.dotask`. No capabilities needed.
2. App record: appstoreconnect.apple.com, Apps, "+", New App. Platform iOS, name from
   `store/app-store.md`, primary language, bundle ID `com.agapecare.dotask`, SKU e.g. `dotask-ios`.
3. Team API key: Users and Access, Integrations, App Store Connect API, Team Keys, "+".
   Name `GitHub Actions`, access **Admin** (needed so Xcode may create signing certificates and profiles).
   Download the `.p8` file: Apple lets you download it only once. Note the **Key ID** and the **Issuer ID**
   shown on that page.
4. Team ID: developer.apple.com/account, Membership details, Team ID (10 characters).

## 3. GitHub secrets (once)

Repository, Settings, Secrets and variables, Actions, New repository secret:

| Secret | Value |
|---|---|
| `ASC_KEY_ID` | Key ID of the API key |
| `ASC_ISSUER_ID` | Issuer ID from the same page |
| `ASC_KEY_P8` | base64 of the `.p8` file (the workflow also accepts the raw file text) |
| `APPLE_TEAM_ID` | Team ID |

Base64 on Windows (PowerShell), copied straight to the clipboard:

    [Convert]::ToBase64String([IO.File]::ReadAllBytes("$HOME\Downloads\AuthKey_XXXXXXXXXX.p8")) | Set-Clipboard

Then keep the `.p8` in a password manager and delete the downloaded copy. Never commit it.

## 4. Build and upload

1. Push the repo to GitHub. Standard runners are free for public repos. In a private repo, macOS minutes
   count against the plan's quota at a multiple of Linux minutes (10x when this was written), and an
   upload run uses two macOS jobs (compile, then upload), so check Settings, Billing before running often.
2. Actions, **iOS**, Run workflow, leave `upload` off: the `compile` job checks that the project
   builds (simulator, unsigned). No secrets needed.
3. Run it again with `upload` on. The `upload` job archives a signed Release build (build number =
   workflow run number) and uploads it to App Store Connect. The API key exists only during the job.
4. App Store Connect processes the build (usually 5 to 30 minutes) and emails you. It then shows
   under TestFlight. Export compliance is already answered by `Info.plist`.

## 5. TestFlight on a real iPhone

1. App Store Connect, the app, TestFlight, Internal Testing, "+" group, add yourself
   (internal testers must be App Store Connect users), add the build.
2. Install TestFlight from the App Store on your iPhone and accept the invite.

Device checklist (iPhone on iOS 16.4 or later; a small screen like an SE helps if you can borrow one):

- [ ] First launch: splash, then the app; no white screen. Rotate; check the notch/Dynamic Island area.
- [ ] Voice tutor: the microphone prompt shows DoTask's text; talking works; the reply plays through the
      **speaker** (not the earpiece) at normal volume, also with the silent switch on; a phone call or Siri
      interruption does not leave it stuck.
- [ ] "Show my camera": camera prompt, preview, the tutor sees it. Deny once and check the Settings hint.
- [ ] Photo of your work: Take Photo and Photo Library both work from the picker.
- [ ] Keyboard: never covers the message composer; the page scrolls back after closing it.
- [ ] Canvas sign-in: opens in the system browser sheet, and after approving you land back **in DoTask**,
      signed in. Also try Cancel.
- [ ] Share/save: "Save as Word" opens the share sheet; Save to Files works; the .docx opens in Files.
- [ ] Backup: export a backup, delete the app, reinstall from TestFlight, restore it.
- [ ] Gemini key survives a restart; no internet gives a clear error; dark mode and larger text are readable.

## 6. Store listing and submission

All texts and answers are in `store/app-store.md`:

1. App Privacy: enter the answers from `app-store.md` (must match `PrivacyInfo.xcprivacy`) and the privacy policy URL.
2. Age rating: answer the questionnaire, ending at **18+**.
3. Screenshots: iPhone 6.9-inch (1320 x 2868 portrait). No iPad screenshots: the app is iPhone only.
4. App Review Information: notes from `store/review-notes.txt` with a review-only Gemini key.
5. Pricing and Availability: an iPhone-only app is also offered on Apple silicon Macs and Apple Vision Pro
   by default. Untick those unless you have tested there (mic, camera and Canvas sign-in differ).
   App Review may still open the iPhone app on an iPad (compatibility mode), so give it a quick try on one if you can.
6. Version 2.1.0: pick the TestFlight build, "Add for Review", submit. Choose manual or automatic release.

## If cloud-managed signing fails

Download the `ios-upload-debug-*` artifact of the failed run (logs and dSYMs). Common causes:

- "No Accounts" or authentication errors: wrong `ASC_KEY_ID`/`ASC_ISSUER_ID`, the key is not **Admin**,
  or `ASC_KEY_P8` is not the base64 of the whole file.
- "No profiles for 'com.agapecare.dotask'": the bundle ID is not registered, or `APPLE_TEAM_ID` is wrong.
- "Your team has no devices": the archive step signs for development first, which needs one registered
  device. Add your iPhone's UDID under Certificates, Identifiers & Profiles, Devices (on Windows, the
  Apple Devices app or iTunes shows the UDID when you click the serial number), then rerun.
- Certificate limit reached: each run on a fresh runner may create an "Apple Development" certificate;
  revoke old ones created via the API under Certificates.
- Not signing but "iOS 26.x is not installed" / missing platform (compile or archive): the selected Xcode's
  iOS platform is not on that runner image. Add `xcodebuild -downloadPlatform iOS` after the
  "Select Xcode 26" step in `ios.yml` (slow, several GB), or pin the runner image's default Xcode instead.

Fallbacks:

- **Codemagic** (codemagic.io): builds on its own Macs, and its automatic iOS signing uses the same
  App Store Connect API key to fetch or create certificates and publish to TestFlight.
- **Manual signing in GitHub Actions**: create an Apple Distribution certificate (CSR and `.p12` made with
  OpenSSL on Windows) and an App Store provisioning profile in the developer portal, store both as base64
  secrets, import them into a temporary keychain in the workflow, and archive with
  `CODE_SIGN_STYLE=Manual` plus `signingStyle manual` and `provisioningProfiles` in `ExportOptions.plist`.
